# 0.11.3 问题修复与工作台体验优化 设计

**状态：** 待评审
**日期：** 2026-08-19
**目标：** 修复三个既有问题（Ctrl+V 重复粘贴、ucode token 无数据、启动内存占用），并优化工作台的会话管理与新建体验。

## 背景

0.11.2 已完成 DSH 数据接入（token 统计 + summary）。0.11.3 聚焦「问题修复」与「工作台/会话管理的 UX 优化」，分两块：

- **A. 问题修复**（3 个）——需先调试定位根因，再修复。
- **B. 功能优化**（6 个）——需求已澄清，直接实现。

## A. 问题修复

### A1. Ctrl+V 粘贴两次

**现状**：`src/terminalKeybindings.js` 已有 `shouldBlockDuplicateClipboardPaste`（阻止 keypress 重复粘贴），且已合并到当前分支（commit `758c5bf`）。但用户仍报告粘贴两次。

**调查方向**（实现阶段用 systematic-debugging）：
1. 确认复现场景：是**终端（xterm）**粘贴两次，还是**普通输入框**（新建会话的 cwd/名称输入框）粘贴两次。
2. 若终端：检查 xterm 6.x（`@xterm/xterm ^6.0.0`）的 `attachCustomKeyEventHandler` 与 `onPaste` 的交互，确认 keydown 已 return false 后是否还有第二条路径（Electron 的默认 paste 事件、`onData` 重复转发）。
3. 若输入框：检查是否有全局 keydown 监听与浏览器默认 paste 叠加。

**修复目标**：Ctrl+V 在所有输入场景只粘贴一次，不影响 Ctrl+Shift+V 与选中文本粘贴。

### A2. ucode 会话 token 无数据

**现状**：`UCodeAdapter extends OpenCodeAdapter`，token 统计复用 `OpenCodeAdapter` 的 `statsReader`（默认调 `loadOpenCodeSessionStats`，用 `runtime.resolveLaunch()` 得到的 ucode 可执行文件读统计）。`ucodeDescriptor.costAvailable: false`。

**调查方向**：
1. 看 `loadOpenCodeSessionStats`（`electron/openCodeStats.js`）实际调用的命令与参数，确认它是否用 OpenCode 特有的 flag（ucode 不支持），以及 ucode 的统计输出格式是否与 opencode 一致。
2. 确认 ucode 的 `resolveLaunch()`（`resolveUCodeLaunch`）返回的可执行文件/入口正确。

**修复目标**：ucode 会话像 opencode 一样产出 token 统计（`inputTokens/outputTokens/cachedInputTokens` 等），写入 `session.stats.tokens` 并展示。

### A3. 启动内存占用高

**现状**：用户反馈刚打开 UCLI 内存占用偏高。静态无法定位，需运行时观察。

**调查方向**：
1. 启动流程 profile（`createOrchestrator` 的初始化阶段），定位大内存分配点：会话恢复（`db.listSessions` 全量）、统计聚合、日志、Skills 发现等。
2. 检查是否有「一次性加载全部数据」而非惰性加载的地方。

**修复目标**：降低冷启动峰值内存（惰性加载、避免重复大对象），不改变功能。

## B. 功能优化

### B1. 菜单栏折叠按钮更明显

**现状**：App.vue 已有折叠按钮（`navCollapsed` + `collapsed-width=64` + 状态持久化），但位于侧栏底部 footer 附近，用户未发现。

**设计**：把折叠/展开按钮移到**侧栏顶部（logo 旁）**，使用更直观的图标（展开时 `MenuFoldOutlined`，收起时 `MenuUnfoldOutlined`），保留现有 `navCollapsed` 状态与持久化；移除底部旧按钮，只保留顶部这一处。

### B2. 会话卡片操作 + 多选批量

**现状**：`SessionCard.vue` 只有「配置」按钮。

**设计**：
- 卡片右上角加「更多」下拉菜单（`Dropdown`），项：**停止 / 重启 / 删除 / 重命名 / 配置**。停止/重启/删除复用现有 `sessions.stop/restart/deleteSession`，重命名复用现有改名逻辑，配置打开现有配置弹窗。
- 卡片悬停时右上角显示**勾选框**，进入多选模式后顶部出现**批量操作栏**：全选、批量删除、批量停止、取消。
- 批量操作复用单会话的 IPC（循环调用），失败项单独提示，不因单个失败中断整体。

### B3. 新建按钮直接弹窗

**现状**：`SessionDetail.vue` 顶部「➕ 新建」是 `$router.push('/')` 跳转。

**设计**：改为**直接弹出新建会话模态框**。为复用，把 Workbench 的 `showNew` 新建模态框抽成独立组件（或全局状态），SessionDetail 与 Workbench 共享。SessionDetail 点「新建」不跳转、就地弹窗。

### B4. 快捷新建（项目分组 + CLI 类型分组下）

**现状**：Workbench 已有「快速新建」（每 adapter 一个按钮，无名称/档案选择）。

**设计**：在**项目分组**和**CLI 类型分组**两级都加「新建」入口，打开简化新建对话框：
- cwd 自动带当前项目目录（不可改或可改）。
- 选 CLI（默认当前分组 CLI）。
- 选填会话名称、配置档案（profile）。
- 确认后创建会话并打开。

与 B3 共用一个新建对话框组件，快捷新建只做「预填 cwd/CLI」的快捷入口。

### B5. 项目打开目录

**现状**：Workbench 项目 header 只显示路径文本。

**设计**：项目 header 加「打开目录」按钮（图标），点击用 Electron `shell.openPath(projectPath)` 打开系统文件管理器。路径无效时提示。

### B6. 定位按钮

**现状**：SessionDetail 无定位功能。

**设计**：SessionDetail 每个窗格加「定位」图标按钮，点击后：
1. 跳转到 Workbench（`/`），携带目标 sessionId。
2. Workbench 滚动到该会话卡片并**高亮**（临时高亮几秒），自动展开对应项目/CLI 分组。

## 关键设计决策

1. **新建入口统一**：B3（SessionDetail 新建）与 B4（快捷新建）复用同一个新建对话框组件，快捷新建只做预填 cwd/CLI。
2. **多选交互**：卡片悬停勾选框 + 顶部批量操作栏（全选/批量删除/批量停止/取消）。

## 范围与优先级

- 本版本 9 个条目全部纳入；「问题修复」3 个依赖运行时调试，实现顺序上先做「功能优化」（需求确定），再并行调试「问题修复」。
- 不引入新依赖；UI 沿用 Ant Design Vue 现有组件。

## 测试

- 功能优化：单元测试覆盖纯逻辑（会话操作映射、批量状态、新建预填、定位路由参数），组件行为用现有 Vue 测试模式验证。
