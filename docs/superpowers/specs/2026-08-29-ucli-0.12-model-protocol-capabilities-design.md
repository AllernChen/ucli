# UCLI 0.12.0 模型协议能力升级设计

**状态：** 已确认，待实施计划

**日期：** 2026-08-29

**目标：** 让 UCLI 依据服务端显式声明的模型协议能力选择模型、投影托管档案和执行真实联调，消除对 `models[0]`、模型名称和厂商的协议猜测。

## 背景

UCLI 0.12.0 已完成 Device Grant Link、Bootstrap、回环 Gateway 代理和服务端模型只读档案投影。2026-08-28 的第三次真实内网 smoke 通过 Preview、首次及幂等 Redeem、强制 Refresh、Bootstrap 和 `/gateway/v1/models`，随后用 `bootstrap.models[0]` 调用 Responses 端点时收到非成功状态。

服务端现已部署模型协议能力合同。Bootstrap 和 Gateway 模型目录都会为每个模型显式返回非空 `protocols`，公开值仅为：

- `openai_responses`
- `openai_chat`
- `anthropic_messages`

客户端当前仍有两处错误假设：

1. 真实 smoke 总是选择 `bootstrap.models[0]` 并调用 Responses。
2. 模型投影会为每个模型同时生成 Codex 和 Claude 档案，无论模型是否支持相应协议。

本次升级以服务端显式能力为唯一事实来源，保持既有安全边界、独立模式和本地能力不变。

## 已确认的设计决策

1. 采用协议能力驱动设计，不按模型 ID、显示名、厂商或目录顺序推断兼容性。
2. Bootstrap 和 Gateway 目录都执行严格解析；`protocols` 缺失、为空或含未知值时 fail closed。
3. Codex 只消费 `openai_responses`；Claude 只消费 `anthropic_messages`。
4. `openai_chat` 是完整支持的公开合同能力和 Gateway 路由，但 0.12.0 不为它新增未经现有档案体系支持的托管 CLI 适配器。
5. live smoke 显式选择 `openai_responses`，覆盖上次失败的回归路径；本地合同测试覆盖全部三种协议。
6. 三类稳定 503 不属于授权失效，不清除 refresh token，不破坏本地档案、Skills、数据或会话，也不自动重放 POST。

## 范围

### 包含

- Bootstrap `models[].protocols` 严格合同。
- Gateway `/v1/models` 模型目录严格合同。
- 协议到本机代理端点的固定映射和按能力选择模型的纯函数。
- Bootstrap 与 Gateway 同模型协议能力一致性验证。
- 服务端模型到 Codex/Claude 档案的能力过滤。
- 三类稳定 503 的安全诊断解析。
- 真实 smoke 的显式协议选择、脱敏失败信息和非空流验证。
- 合同夹具、投影、代理、凭证保留、live smoke 和交付文档测试。

### 不包含

- 原生 `gemini` 能力、配置项或 Gateway 端点。
- 根据模型名称或厂商补全协议。
- 为 `openai_chat` 新增 OpenCode、U-Code 或其他托管档案体系。
- 兼容缺少 `protocols` 的旧服务端响应。
- 对模型 POST 请求做自动重试。
- 改变 Device Grant Link、refresh token、安全存储或 Skills 安装合同。

## 核心合同

### 公共协议定义

在 `electron/serverConnection/contracts.js` 暴露不可变协议枚举和严格解析器。协议数组必须：

- 是数组；
- 至少包含一个元素；
- 每个元素是三个公开枚举之一；
- 不接受 `gemini` 或其他内部/未知值。

协议顺序不用于优先级判断。目录一致性比较按集合语义处理，因此服务端返回顺序不同不构成不一致。解析后的模型仍保留服务端顺序，以便显式协议筛选后的结果稳定。

### Bootstrap 模型

解析结果：

```js
{
  id,
  displayName,
  contextSize,
  protocols
}
```

`id`、`displayName` 和正整数 `contextSize` 继续沿用现有严格合同；新增 `protocols` 后不设置默认值。

### Gateway 模型目录

新增 `parseGatewayModelsResponse`，要求顶层为 `{ object: 'list', data: [...] }`，每个项目包含：

```js
{
  id,
  object: 'model',
  ownedBy,
  displayName,
  contextSize,
  protocols
}
```

线缆字段 `owned_by`、`display_name`、`context_size` 在解析边界转成客户端命名。未知字段可以忽略，但必填字段不能缺失或由其他字段推导。

### 目录一致性

真实 smoke 在发送模型请求前验证：

- 所选 Bootstrap 模型在 Gateway 目录中存在；
- 同一模型的 `protocols` 集合一致；
- 所选协议同时出现在两个目录中。

任何条件不满足都在 `model-directory` 阶段 fail closed，不发送猜测的模型请求。0.12.0 不要求客户端后台周期性拉取 Gateway 目录，也不让透明代理改写服务端目录响应。

## 协议选择与端点

集中维护固定映射：

| 公开协议 | 本机代理端点 | 服务端端点 |
| --- | --- | --- |
| `openai_responses` | `/v1/responses` | `/gateway/v1/responses` |
| `openai_chat` | `/v1/chat/completions` | `/gateway/v1/chat/completions` |
| `anthropic_messages` | `/anthropic/v1/messages` | `/gateway/anthropic/v1/messages` |

选择函数接收已解析模型目录和一个显式协议，返回第一个声明该能力的模型或 `null`。它不得：

- 回退到原目录第一项；
- 根据模型属性猜测协议；
- 把 `gemini` 映射为客户端可选协议。

`openai_chat` 能力覆盖服务端把 Gemini 等内部上游转换成 OpenAI Chat 的情况；客户端只看到并选择 `openai_chat`。

## 服务端档案投影

`electron/serverConnection/modelProjection.js` 根据适配器实际 wire contract 生成档案：

| 客户端适配器 | 必需协议 | 投影结果 |
| --- | --- | --- |
| Codex | `openai_responses` | 生成 `wireApi: 'responses'` 的只读服务端档案 |
| Claude | `anthropic_messages` | 生成 bearer + `/anthropic` base URL 的只读服务端档案 |

模型可以声明多个协议，因此可能同时生成 Codex 和 Claude 档案。只声明 `openai_chat` 的模型不会生成当前不兼容的托管档案；现有本地档案和用户默认选择保持不变，界面自然呈现“没有兼容的服务端模型”，而不是伪造可启动项。

协议不需要新增数据库列：生成的每行档案已经由 `adapter_id` 唯一表达其消费协议，稳定 profile ID 继续包含 adapter ID。Bootstrap 刷新后，失去相应协议的投影会按现有 reconciliation 语义删除并撤销关联的本机会话 authority。

## Gateway 路由失败与安全诊断

新增安全诊断解析，识别以下 HTTP 503：

| code | retryable | 客户端处理 |
| --- | --- | --- |
| `model_protocol_unavailable` | `false` | 重新按能力筛选；不重试当前 POST |
| `model_channel_unavailable` | `true` | 标记可重试，但当前 smoke/代理不自动重放 POST |
| `upstream_unavailable` | `true` | 标记可重试，但当前 smoke/代理不自动重放 POST |

安全诊断仅包含：

```js
{
  httpStatus,
  contentType,
  cacheControl,
  stableCode,
  requestId,
  retryable
}
```

稳定 503 必须验证：

- HTTP 状态为 503；
- `Cache-Control` 为 `no-store`；
- `X-UCLI-Request-ID` 与 JSON `requestId` 存在且一致；
- JSON `statusCode`、`code`、`message` 和 `retryable` 符合稳定合同。

解析器不返回响应正文、完整响应头、token、Cookie、供应商信息或完整堆栈。未知或格式错误的 503 记录为普通脱敏 Gateway 失败，不能被误判为授权失效。

本机代理保持现有安全行为：只对 GET `/v1/models` 的 401 执行一次强制 Refresh 后重试；所有模型 POST 均不自动重放。503 原样转发给发起请求的 CLI，同时连接管理器和凭证存储不做清除动作。

## 真实 smoke

`test/server-integration-smoke.test.mjs` 增加非秘密环境输入 `UCLI_SERVER_SMOKE_PROTOCOL`，只接受三个公开协议。下一次 0.12.0 联调显式设置为 `openai_responses`。

模型阶段顺序：

1. 严格解析 Bootstrap 模型目录。
2. 获取并严格解析 Gateway 模型目录。
3. 按显式协议选择 Bootstrap 模型。
4. 验证所选模型在 Gateway 目录中存在且协议一致。
5. 根据固定映射构造对应的最小流式请求。
6. 收到响应后先捕获脱敏 HTTP 诊断。
7. 仅在成功响应并收到非空数据后标记 `modelStream` 通过。
8. 模型流成功后才继续 Skills catalog/download hash 验证。
9. 无论成功或失败都执行既有数据库、环境变量和临时目录清理。

失败抛出的错误只携带允许回传的脱敏诊断，避免 Node 测试输出意外打印响应正文或授权材料。一次性 URL 仍只允许从安全输入写入当前进程环境，完整 smoke 只运行一次。

## 测试策略

### 合同测试

- Bootstrap 和 Gateway fixtures 分别覆盖三种协议。
- 拒绝缺失 `protocols`、空数组、未知协议和 `gemini`。
- 验证协议数组顺序不影响目录一致性。
- 验证按协议选择正确模型，无匹配时返回 `null`。
- 验证固定协议端点映射。

### 投影测试

- Responses-only 模型只生成 Codex 档案。
- Anthropic-only 模型只生成 Claude 档案。
- 多协议模型生成相应的两个档案。
- Chat-only 模型不生成伪造档案。
- 协议移除会撤销已跟踪的相关服务端运行时。
- 本地用户档案和绑定不受影响。

### Gateway 与凭证测试

- 三类稳定 503 的状态、头、字段和 `retryable` 完整匹配。
- 503 不触发 Refresh、凭证删除或 POST 重放。
- 独立模式及本地能力继续可用。
- 授权到期仍只走既有 Device Grant 到期路径。

### 验收顺序

1. 相关单元与合同门。
2. 0.12.0 本地完整验证。
3. 使用平台新建的一次性授权执行一次 live smoke。
4. 更新 `docs/release-acceptance.md`、`docs/ucli-client-protocol.md`、`docs/ucli-client-registration-upgrade.md`。
5. 执行文档和 release verification。

## 交付与回传

回传只包含服务端允许的脱敏 YAML 字段。除既有字段外，必须记录：

- `selectedModelId`
- `selectedProtocol`
- `httpStatus`
- `contentType`
- `cacheControl`
- `stableCode`
- `requestId`
- `retryable`
- `streamReceivedNonEmptyData`

不得回传 Connection URL、fragment、token、Authorization/Cookie、响应正文、完整响应头、真实身份、供应商密钥、完整堆栈或可复原这些信息的编码内容。

真实联调前还需由服务端提供本次部署的短提交 SHA 和 runtime image digest；不沿用上一轮 `28bdc40` / `sha256:ef15c26f8d80`，除非服务端明确确认本次部署仍是该基线。

## 风险与控制

1. **旧服务端兼容诱惑：** 不增加默认协议；旧响应直接失败，促使部署合同一致。
2. **Chat 能力被误认为现成档案：** 仅支持合同解析、代理路由和测试，不扩展 0.12.0 档案架构。
3. **自动重试造成重复副作用：** 模型 POST 不自动重放，`retryable` 仅作为安全诊断和上层用户决策依据。
4. **目录暂时不一致：** live smoke 在请求前 fail closed；不拿任一目录替代另一目录。
5. **错误输出泄密：** 失败对象先归一化到白名单字段，再进入断言和测试输出。
6. **服务端失败拖垮独立模式：** 路由失败不改变连接授权状态，不删除凭证或本地资源。

## 完成标准

- 客户端不存在使用 `models[0]` 推断 Gateway 协议的路径。
- Bootstrap/Gateway 协议合同、选择函数和目录一致性测试通过。
- 模型投影只生成协议兼容的 Codex/Claude 档案。
- 三类稳定 503 产生完整脱敏诊断且保留凭证与本地能力。
- 显式 `openai_responses` live smoke 收到非空流式数据并完成 Skills hash 验证与清理。
- 三份 0.12.0 交付文档和 release verification 通过。
