# 0.11.2 DSH 数据接入设计：token 统计 + summary 接入

**状态：** 待评审
**日期：** 2026-08-18
**目标：** 让 DeepSeek Harness（DSH）Web 会话拥有与其他 AI CLI 对齐的 token 统计与 summary 能力。

## 背景

0.11.1 把 DSH 重构为 Web-only，UCLI 通过 loopback HTTP API（`127.0.0.1:<port>`）给 DSH web 注册 workspace 并预开会话。排查 DSH 的 API 面后确认，DSH web 已经暴露了 token / 会话 / 事件数据，无需再走 0.11.0 的 bridge 插件方案（该方案因 DSH 无 CLI TUI 而失败、已被 quarantine）：

| DSH loopback API | 内容 |
|---|---|
| `session.list` | 每个 native session 的 `sessionId`、`updatedAt`、`tokenUsage`（`uncachedInputTokens`/`outputTokens`/`cacheReadTokens`/`cacheWriteTokens`） |
| `session.export` | ZIP 归档，内含 `session.jsonl`（逐事件日志）+ `subagents/*` + `media/*` |
| `host.describe` | provider / model / cwd |

现有实现对照：
- token 统计：Claude 取 `result.usage`、Codex 取 `tokenUsage` 事件，均映射到 `session.stats.tokens = { input, output }` 并 `db.upsertStats`。DSH 的数据在 `session.list`。
- summary：用 claude/opencode CLI 作执行器，从 `sessionHistoryService.loadRange` 读会话转录生成报告。`loadRange` 支持 claude/codex/opencode/ucode，**不支持 DSH**。

## 决策

1. **通信方式**：loopback API（轮询 pull），不写插件。
2. **token 实时性**：轮询（5–10s），不做 SSE 实时订阅。
3. **summary 方向**：DSH 会话作「被总结目标」，执行器仍用 claude/opencode。
4. **token 展示**：全链路对齐，`statsOwner` 从 `native` 改为 `ucli`（权限/历史仍 native）。
5. **summary 时间筛选**：按 native session 的 `updatedAt` 落在 `[start, endExclusive)` 筛选，不做 session 内逐条时间过滤。

## 架构

### 1. capabilities 契约变更（stats 维度独立）

DSH web 的 `statsOwner: 'native' → 'ucli'`，`permissionOwner`/`historyOwner` 保持 `native`。同步放宽三处「web surface 要求三 owner 全 native」的一致性检查，允许 `web + permission/history=native + stats=ucli`：

- `electron/adapters/adapterCapabilities.js` 的 `DSH_WEB_CAPABILITIES`
- `src/sessionMaintenancePresentation.js` 的 `coherentOwnership`（web 分支不再要求 stats 也是 native）
- `src/stores/sessions.js` 的 `rendererSessionCapabilities` 的 `nativeWeb` 判定
- `electron/usage/statsOwnership.js` 的 `sessionUsesUcliStats`（放宽 `surface === 'terminal'` 条件，改为只依据 `statsOwner === 'ucli'` 与 gateway/bridge 语义）

语义自洽：「统计」是只读镜像，UCLI 拉取展示不「管理」；权限/历史仍由 DSH iframe 原生管理。

### 2. `electron/adapters/dshWebClient.js`（新）

封装 DSH loopback API，复用 0.11.1 的 fetch + JSON-RPC envelope 模式：

- `listSessions(url)` → `[{ sessionId, updatedAt, tokenUsage }]`
- `exportSession(url, sessionId)` → 解压 ZIP、取 `session.jsonl` 原文
- `aggregateTokenUsage(url)` → 各 native session token 求和

每个方法都对 URL 做 loopback origin 校验（同 0.11.1 的 `isDshWebLoopbackOrigin`），任何失败返回稳定错误而非抛原始错误。

### 3. token 统计轮询器

orchestrator 级组件，每 5–10s 遍历活跃 DSH web 会话（`session.surfaceState.url` 有值即活跃），调 `aggregateTokenUsage`：

- `input = uncachedInputTokens + cacheReadTokens`
- `output = outputTokens`
- `cacheWriteTokens` 忽略

写 `session.stats.tokens`、`db.upsertStats`，并广播事件刷新渲染层。

### 4. summary 接入（`sessionHistoryService` DSH 分支）

`loadRange({ sessionId, start, endExclusive })` 加 DSH 分支：

1. 从 `session.surfaceState.url` 取 DSH web 地址；
2. `listSessions` 拿 native session 列表，按 `updatedAt ∈ [start, endExclusive)` 筛选；
3. 对命中的 native session 调 `exportSession` 取 `session.jsonl`；
4. 解析 JSONL 为 `items`（沿用现有 historyService 的归一化 item 形状），喂给 `evidenceCollector`；
5. 执行器仍是 claude/opencode。

注意：DSH 会话无 UCLI 层 `cliSessionId`，此分支不经过 `isSafeNativeSessionId` 门，改由 `surfaceState.url` 有效性门代替。

## 数据流

**token：**
```
DSH web 进程（session.jsonl 持久化 tokenUsage）
  ← GET /api/session.list（轮询器 5–10s）
  → aggregateTokenUsage 求和
  → session.stats.tokens = { input, output }
  → db.upsertStats + UI 刷新
```

**summary：**
```
summary job（period: start/endExclusive）
  → loadRange（DSH 分支）
  → listSessions 按 updatedAt 筛选 native sessions
  → exportSession 解压 ZIP 取 session.jsonl
  → 解析 items → evidenceCollector
  → claude/opencode 执行器 → 报告
```

## 错误处理

- 轮询失败（web 进程退出 / URL 失效 / 网络错误）：跳过该会话、不抛错，下轮重试；不写脏 token。
- `exportSession` 失败：稳定错误码 `DSH_HISTORY_UNAVAILABLE`，summary 对缺失来源降级为「会话来源不可用」。
- web 未就绪（`surfaceState.url` 为空）：token 不更新；summary 报「会话未就绪」。
- token 字段缺失：按 0 处理，不抛错。

## 测试

- `dshWebClient`：mock fetch 测 `listSessions` 聚合、`exportSession` 解压、loopback origin 校验、失败降级。
- 轮询器：定时触发、token 映射、失败跳过与重试、web 退出时停止。
- capabilities：`web + stats=ucli` 契约在三处判定中一致通过，`sessionUsesUcliStats` 对 DSH 返回 true。
- `sessionHistoryService` DSH 分支：按 `updatedAt` 时间筛选、JSONL 解析为 items、无 URL 时降级。
- summary 端到端：DSH 会话进入 summary 源列表并产出报告。

## 风险与开放问题

1. **DSH summary 依赖 web 进程存活**：`session.export` 走 loopback API，web 退出后 `surfaceState.url` 失效、转录拿不到。已知限制，本设计不引入「直读 `~/.dsh` 文件」兜底（方案 C 已排除）。若实际体验不可接受，可在后续版本评估「summary 时临时拉起 DSH web 再导出」。
2. **ZIP 解压依赖**：`session.export` 返回 ZIP，UCLI 当前未依赖 zip 库。计划引入 `fflate`（DSH 同款、零依赖、轻量）作解压实现，需在实现阶段确认版本与打包体积。
3. **token 映射语义**：`cacheReadTokens` 计入 input、`cacheWriteTokens` 忽略，是与现有 `{input, output}` 二字段模型的最小对齐；若后续要展示缓存命中/成本，需扩展 stats 模型（本次不做）。
4. **费用统计**：DSH API 不暴露费用数字（`costAvailable: false` 不变），本次只做 token 数量，不做费用换算。
