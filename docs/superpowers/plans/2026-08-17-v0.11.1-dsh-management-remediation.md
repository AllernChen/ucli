# UCLI 0.11.1 DeepSeek Harness Management Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 UCLI 0.11.1 中撤销错误的 DSH CLI TUI 假设，把 DeepSeek Harness 重构为可由 UCLI 安装、升级、修复、卸载并启动 Web 的受管运行时，并把 DSH 官方 Skills 根纳入统一技能管理。

**Architecture:** 将 DSH 分成四个边界：UCLI 私有 Runtime 管理器、DSH 原生 profile/legacy bridge 管理器、Web-only 会话适配器、共享 Skills 投影层。0.11.1 只把官方 Web 作为交互面；既有 TUI 会话和 profile 保留为不可启动的 legacy 数据，不自动删除。Runtime 采用固定版本、固定 registry、staging 安装、完整性复核和原子切换；Skills 直接管理 `.dsh/skills`，并通过现有 `.agents/skills` 投影实现 Codex/DSH 共享而不复制。

**Tech Stack:** Electron 43、Node.js 24、Vue 3、Pinia、Node `child_process`/`fs`、npm CLI、pnpm、Node test runner、electron-vite、electron-builder。

## Global Constraints

- 应用版本为 `0.11.1`；兼容 DSH 基线仍固定为 `@deepseek-ai/dsh@0.1.0-rc.6`。
- DSH npm 发布物必须匹配 SHA-1 `de9fbf39056c7f4e658a3e284cb1d66ebc86d040` 和 integrity `sha512-brpZfED7ieRa2PQ5tUxMhHrM1pb2CmKFVM/f6yMULBDMicahk+Z2OsHgTwTDnoiZm23Ftu9rQz0NN4pflaoJcg==`。
- 受管 pnpm 固定为 `10.30.3`；renderer 不得提交包名、版本、registry、命令、路径或脚本开关。
- 官方开源仓库和 rc.6 发布物没有 CLI TUI app、TUI bundle 或 TUI profile template；`dsh --profile tui` 只是自定义 profile 名。
- 0.11.1 新建 DSH 会话只能使用 Web；不得创建、恢复、重启或宣传 DSH TUI。
- 官方 Web 启动 argv 仍固定为 `dsh web --host 127.0.0.1 --port 0`，`shell: false`；readiness、CSP、iframe sandbox、输出预算和进程树清理沿用 0.11.0 安全契约。
- `ucli-dsh-bridge-0.11.0.tgz` 在 0.11.1 安装包中继续保留，防止既有 profile 的 `file:` 依赖失效；不再自动安装或用于新会话。
- 升级不得自动删除用户的 DSH_HOME、profiles、sessions、plugins、Skills 或 legacy bridge；删除 legacy bridge 和受管 Runtime 都必须由用户显式触发。
- UCLI 私有 Runtime 位于 `app.getPath('userData')/runtimes/deepseek-harness`；DSH 用户数据仍遵循显式 `DSH_HOME` 或 `~/.dsh`，Runtime 和数据目录不得混用。
- Runtime 安装只能调用验证过的绝对 Node/npm 入口，固定 `https://registry.npmjs.org`，使用 `--ignore-scripts --no-audit --no-fund`，并在切换前验证 package-lock integrity、包名、版本和 bin。
- Runtime 安装、修复、升级和删除前必须确认没有 UCLI-owned DSH 子进程；未确认进程树终止时不得替换或删除 Runtime。
- DSH Skills 默认根按官方顺序管理：项目 `.dsh/skills`、项目 `.agents/skills`、用户 `$DSH_HOME/skills`、用户 `~/.agents/skills`；custom/bundled 根只读展示。
- `.agents/skills` 是共享物理源；同一 Skill 不得因 Codex 和 DSH 同时可见而复制文件或创建两条安装记录。
- Skills 支持 `<name>/SKILL.md` 和 `<name>.md`；写操作继续使用 UCLI 现有安全文件事务、源审查和显式确认。
- 所有 renderer IPC 返回值只包含 allowlist 状态、版本、scope、稳定错误码和布尔能力，不返回 Runtime 路径、DSH_HOME、registry 输出、stdout/stderr、token 或 endpoint。
- Windows 与 macOS 都必须完成原生 Web 启动、Runtime 安装/修复/卸载、Skills 四根发现和进程清理验收；一个平台不能代替另一个平台。

## Stage 2 Design Records

### Solution Design Record: SDR-0.11.1-DSH-01

**Approved problem:** 0.11.0 将一个 `dsh-base + @ucli/dsh-bridge` 自定义 profile 当作 CLI TUI。该进程可以完成 bridge hello，却没有终端 renderer/input loop，因此真实用户得到空白或启动失败的“DSH TUI”会话。

**Approved solution:**

1. 新会话只开放 DSH Web，现有 Web 原生权限/历史/统计所有权不变。
2. TUI 配置改为 legacy unavailable；既有行保留，禁止启动，并提供“新建 Web 会话”迁移动作。
3. UCLI 增加私有 Runtime 管理器；系统 DSH 仍可只读发现，兼容的受管 Runtime 优先启动。
4. Profile Center 负责 Runtime、profiles 和 legacy bridge 状态；不把 profile 结构有效等同于 UI 可用。
5. Skills Center 把 DSH 从 project-only 虚拟消费者升级为真实 `.dsh/skills` 目标，同时复用 `.agents/skills`。
6. bridge 源码和 0.11.0 tgz 暂时保留用于兼容、诊断和显式卸载；不注入 Web，不创建 bridge server。

**Explicit exclusions:**

- 不接入第三方 DeepSeek-TUI；它不是 DeepSeek Harness 的官方内置 surface。
- 不在 0.11.1 实现 UCLI 原生语义聊天 surface。
- 不把 Headless 冒充交互会话；0.11.1 只预留受管运行接口和诊断，工作台不创建 Headless 卡片。
- 不提供任意 DSH plugin marketplace；profile plugin 的通用安装/升级留到后续版本。
- 不自动迁移或删除用户 profile 中的 `@ucli/dsh-bridge`。

## Verification and Rollback Plan

### Acceptance mapping

| Requirement | Automated evidence | Manual evidence |
|---|---|---|
| No DSH TUI creation/start | Task 1/4 config, adapter and template tests | Legacy database + new session flow |
| Managed install/repair/upgrade/remove | Runtime transaction tests | Clean/failed install on Windows/macOS |
| Web remains usable and isolated | Existing Web lifecycle suite + Task 4 | Two concurrent Web hosts per platform |
| Profiles preserved | Profile manager rollback tests | Inspect pre/post profile metadata |
| Legacy bridge not auto-removed | Profile status/release artifact tests | Upgrade existing 0.11.0 install |
| Four default DSH Skills roots | Skills discovery/service tests | One Skill per root |
| Shared `.agents` dedupe | Projection and DB installation tests | Codex+DSH dual-consumer install |
| No path/output leakage | IPC/presentation tests | Diagnostics and UI inspection |
| Release 0.11.1 | version/docs/artifact tests | Installer About/version screen |

### Environment prerequisites

- Windows x64 VM with Node 24/npm 11 access to `registry.npmjs.org`.
- macOS arm64 host with Node 24/npm 11.
- A clean user account and a separate upgrade account containing a 0.11.0 database, `TUI` profile, installed bridge and sample Skills.
- Network failure injection or local proxy capable of cutting npm during download.
- Non-sensitive project repositories with `.git` roots for project Skills discovery.

### Migration and backup

1. Application/database schema remains backward-compatible; no destructive DB migration is required.
2. Persisted DSH TUI adapter config is normalized in memory to `legacy-tui`; the database row remains available for rollback and audit.
3. Runtime manager backs up only its own selected Runtime directory before atomic replacement.
4. Legacy bridge removal backs up exactly the four DSH profile metadata files already covered by 0.11.0 transaction tests.
5. Skills write operations retain existing UCLI installation records and file transaction backups; visibility metadata does not duplicate records.
6. The release retains bridge tgz 0.11.0 so an upgraded profile's file dependency remains resolvable.

### Stop conditions

- DSH package or lock integrity differs from the pinned values.
- npm requires lifecycle scripts for a successful supported install.
- Owned DSH process termination cannot be confirmed before Runtime mutation.
- Runtime rollback cannot restore the last selected healthy installation.
- Any test observes writes outside the managed Runtime, selected profile metadata or selected Skill target.
- Existing Codex/Claude/OpenCode/U-Code Skills projection tests regress.
- Web CSP gains loopback `connect-src`, `unsafe-eval`, webview, unrestricted sandbox tokens or non-loopback frame origins.
- Either native platform cannot pass install/repair/remove and Web process cleanup acceptance.

### Rollback procedure

1. Stop new Runtime mutations and DSH Web launches.
2. If a Runtime transaction is active, wait for its owned npm tree to exit; restore the manager's backup only after termination is confirmed.
3. Reinstall UCLI 0.11.0 without deleting userData or DSH_HOME. The retained database rows, profiles and Skills remain readable; the 0.11.1 managed Runtime directory is ignored by 0.11.0.
4. Do not convert `legacy-tui` rows back by rewriting the database. If 0.11.0 is used temporarily, keep those sessions offline unless the user independently supplies a real compatible TUI bundle.
5. If legacy bridge removal was attempted, use the preserved four-file backup or reinstall bridge from the retained 0.11.0 tgz only after explicit user approval.
6. Verify post-rollback: ordinary four CLI adapters start, DSH Web starts from a compatible system Runtime, DSH_HOME/profile/Skills file counts match the pre-upgrade record, and no managed install process remains.
