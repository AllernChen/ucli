# UCLI 0.7.x CC Switch 与 Codex 深度兼容 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不接管 CC Switch 数据库、不覆盖 Codex 用户配置的前提下，让 UCLI 0.7.x 正确跟随外部 live 配置、稳定恢复 Codex 原生会话，并准确统计多 rollout 与 fork 会话用量。

**Architecture:** CC Switch 或用户继续负责写入 Codex live 配置；UCLI 只读取经过脱敏的运行时配置快照，并按每个工作台会话的 Provider 策略决定是否传递 `-c model_provider=...`。Codex 原生会话发现、历史合并和用量解析从 `orchestrator.js`/adapter 中拆成独立服务，统一使用可配置的 Codex 数据目录。

**Tech Stack:** Electron 32、Vue 3、Pinia、Node.js ESM、node-pty、sql.js、`smol-toml@1.4.2`、Node test runner、electron-vite、electron-builder。

## Global Constraints

- 版本线固定为 `0.7.x`：`0.7.0` 共存基础，`0.7.1` 会话恢复加固，`0.7.2` 用量正确性与性能。
- 当前工作区中尚未发布的 Codex `resume` 修复作为 `0.7.0` 基线，不单独发布 `0.6.1`。
- UCLI 不读取或写入 `~/.cc-switch/cc-switch.db`，不依赖 CC Switch 私有数据库结构。
- UCLI 0.7.x 不写入 `auth.json`、`config.toml`、Codex rollout JSONL、`session_index.jsonl` 或 `state_*.sqlite`。
- Renderer 只能收到 Provider 名称、配置目录、修改时间和是否需要重启；API Key、OAuth Token、完整 TOML 不得离开 Electron main process。
- 运行中的 Codex 进程不因配置变化自动重启；UCLI 只提示用户，由用户决定何时重启。
- 新 Codex 会话默认跟随 live 配置；恢复原生会话默认使用其源 Provider，源 Provider 不存在时回退 live Provider 并显示警告。
- Windows 10+ 与 macOS 12+ 均为发布门槛；路径比较必须兼容 Windows 大小写与分隔符差异。
- TOML 只读解析固定使用 `smol-toml@1.4.2`，精确锁定版本；0.7.x 不再用正则判断 Codex active Provider。
- 所有行为变更采用 TDD；每个任务先看到目标测试失败，再写最小实现。
- 若直接复制 CC Switch 源码片段，必须新增 `THIRD_PARTY_NOTICES.md` 并保留 MIT 版权声明；仅复现行为时不得保留来源项目的实现细节或品牌文案。

```js
import { parse as parseToml } from 'smol-toml'

export function resolveCodexHome({ configuredDir, env = process.env, userHome }) {
  const selected = String(configuredDir || env.CODEX_HOME || join(userHome, '.codex')).trim()
  return resolve(selected)
}

export function parseCodexProviderIdentity(text) {
  const parsed = text.trim() ? parseToml(text) : {}
  const availableProviders = ['openai', ...Object.keys(parsed.model_providers || {})]
  const declared = typeof parsed.model_provider === 'string' ? parsed.model_provider : 'openai'
  return {
    currentProvider: availableProviders.includes(declared) ? declared : 'openai',
    availableProviders: [...new Set(availableProviders)]
  }
}

export function readCodexRuntimeSnapshot(codexHome) {
  const configPath = join(codexHome, 'config.toml')
  const text = existsSync(configPath) ? readFileSync(configPath, 'utf8') : ''
  const identity = parseCodexProviderIdentity(text)
  return {
    codexHome,
    configPath,
    ...identity,
    mtimeMs: existsSync(configPath) ? statSync(configPath).mtimeMs : 0
  }
}
```

```js
export function buildCodexArgs(session) {
  const args = [
    '--no-alt-screen',
    '-c', 'tui.notifications=true',
    '-c', 'tui.notification_method="osc9"',
    '-c', 'tui.notification_condition="always"'
  ]
  if (session.cliSessionId) args.push('resume', session.cliSessionId)
  if (session.providerPolicy !== 'live' && isSafeProviderName(session.providerOverride)) {
```

## 最终验收矩阵

| 场景 | 预期行为 |
| --- | --- |
| 未安装 CC Switch | UCLI 使用 `CODEX_HOME` 或默认 `~/.codex`，功能完整 |
| CC Switch 切换 Provider，Codex 会话未启动 | 下次启动读取新 live 配置，不传旧 Provider override |
| CC Switch 切换 Provider，Codex 正在运行 | 当前进程保持不变，UCLI 显示“重启后生效” |
| 恢复历史会话且源 Provider 存在 | 默认传 `-c model_provider=<source>` 与 `resume <id>` |
| 恢复历史会话且源 Provider 已删除 | 回退当前 live Provider，显示明确警告 |
| explicit Provider 已删除 | 阻止启动并要求重新选择，不静默回退 |
| UCLI 重启且 native ID 尚未入库 | 按 cwd 和创建时间恢复原 native ID |
| 同一 session ID 有多个 rollout | 历史合并、统计不重复、resume 使用相同 ID |
| archived root session | 可发现、可导入、标记已归档 |
| subagent rollout | 不进入用户可导入会话列表 |
| 20 MB rollout 追加一条事件 | 增量读取新增字节，不重读全文件 |
| fork 重放父 Token | 历史保留，统计扣除 replay prefix |
| 配置含 API Key/OAuth | Renderer、日志、诊断和错误消息均不出现密钥 |
