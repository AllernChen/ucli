# UCLI v0.6.0 U-Code Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release UCLI 0.6.0 with U-Code as a first-class AI CLI alongside Claude Code, Codex, and OpenCode.

**Architecture:** Treat U-Code as an OpenCode-protocol-compatible runtime while keeping its executable, environment variables, native sessions, and exports isolated. Reuse the existing OpenCode permission, PTY, statistics, history, and Gateway behavior through a runtime profile instead of copying the adapter.

**Tech Stack:** Electron, Node.js ESM, Vue 3, node-pty, Node test runner

## Global Constraints

- UCLI release version is exactly `0.6.0`.
- U-Code executable is `ucode`; distribution uses native archives from `AllernChen/U-Code` GitHub Releases rather than npm.
- U-Code receives permissions through `UCODE_CONFIG_CONTENT` and client identity through `UCODE_CLIENT`.
- OpenCode behavior and its `OPENCODE_*` environment remain unchanged.
- U-Code native sessions must be discovered and exported with U-Code itself, never OpenCode.
