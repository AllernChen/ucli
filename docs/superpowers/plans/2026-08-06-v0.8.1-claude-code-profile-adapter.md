# UCLI 0.8.1 Claude Code 配置档案适配器 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 0.8.0 配置档案中心中完整接入 Claude Code，使用户可以为不同项目和会话安全选择 Claude 登录态、Anthropic API Key 或兼容网关，而不修改 `~/.claude/settings.json`、OAuth 数据或项目配置。

**Architecture:** 复用 0.8.0 的 profile 表、绑定、revision、加密密钥、IPC 和页面框架，新增 `claude` ProfileAdapter。Claude Code 没有与 Codex 等价的原生 profile 文件，因此档案只保存在 UCLI，并在 PTY 启动时转换为 `--model` 和进程级环境变量；现有 UCLI hook 继续通过临时 `--settings` JSON 合并，密钥绝不写入该临时文件。

**Tech Stack:** Electron 32、Vue 3、Pinia、Ant Design Vue 4、Node.js ESM、node-pty、sql.js、Electron `safeStorage`、Node test runner、electron-vite、electron-builder。

## Global Constraints

- 开始前 `0.8.0` 配置档案中心必须完成并通过验收；本计划不复制 profile CRUD、binding、revision 或 secret 表。
- 版本固定为 `0.8.1`；不在本版本同时接入 OpenCode 或 U-Code。
- 不读取、写入或复制 Claude Code OAuth、Keychain、credential、`.credentials.json` 或登录 token。
- 不修改 `~/.claude/settings.json`、项目 `.claude/settings.json`、`.claude/settings.local.json`、`CLAUDE.md` 或 managed settings。
- `--settings` 只承载 UCLI hook 与硬黑名单；API Key、Bearer Token 和 Base URL 只通过目标 PTY 的 `env` 注入。
- UCLI 不绕过 Claude Code managed settings。若组织限制替换了请求模型，UI 展示 Claude init 事件报告的实际模型。
- “系统当前”保留启动 UCLI 时继承的 Claude 环境和登录行为；具体档案不得修改 `process.env`。
- “Claude 登录态”档案在目标子进程中清除 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL` 与第三方云路由开关，确保不会被继承变量静默覆盖。
- API Key 档案只设置 `ANTHROPIC_API_KEY`；Bearer 档案只设置 `ANTHROPIC_AUTH_TOKEN`。两者互斥。
- 使用 UCLI 托管密钥时设置 `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`，降低 Bash、hooks、MCP stdio 子进程读取 Provider 凭据的风险。
- 外部 Base URL 必须为 HTTPS；HTTP 只允许 loopback。不得包含 URL 用户名、密码、控制字符或 fragment。
- 模型必须作为独立 argv 传递，并通过安全标识符校验；禁止把用户输入拼成 shell 字符串。
- 0.8.1 不提供 fallback model；Claude Code 的 `--fallback-model` 仅适用于 `--print`，UCLI 的交互式 PTY 不支持该行为。
- 运行中的 Claude PTY 不自动重启；档案切换沿用 0.8.0 的 desired/active/pending 三态。
- 恢复历史会话默认不绑定应用/项目档案；只有用户显式选择档案才覆盖恢复时的模型/连接方式。
- Windows 10+ 与 macOS 12+ 为发布门槛；Windows 继续使用安全的 `cmd.exe /c claude <argv...>` 路径，不改回 PowerShell `-Command`。
- 所有行为变更采用 TDD；每个任务先看到目标测试失败再实现。

新建 drawer 提供三种连接方式：

1. `subscription`：使用现有 Claude Code 登录态，无密钥、无 Base URL；
2. `api_key`：Anthropic API Key，可选官方 API 或兼容 Base URL；
3. `bearer`：Authorization Bearer Token，必须配合网关 Base URL。

共同字段：档案名称和主模型。0.8.1 不提供 fallback model、任意环境变量、任意 settings JSON、Bedrock/Vertex/Foundry 凭据编辑器，也不提供 context window 输入框。

## 数据和接口

`ai_cli_profiles.config_json` 对 Claude 只允许以下结构：

```js
{
  connectionMode: 'subscription' | 'api_key' | 'bearer',
  baseUrl: null | string
}
```

通用 `model` 列保存主模型。`provider_id` 固定保存 `claude-subscription`、`anthropic-api` 或 `anthropic-bearer`，用于列表过滤和诊断，不用于启动参数。

新增 `electron/aiCliProfiles/claudeProfileAdapter.js`：

```js
export const claudeProfileAdapter = {
  id: 'claude',
  validateDraft,
  sanitiseConfig,
  resolveLaunch,
  reconcile
}
```

导出函数：

- `isSafeClaudeModel(value) -> boolean`
- `normaliseClaudeProfileDraft(draft) -> { common, config, secretAction }`
- `buildClaudeProfileArgs({ session, profile }) -> string[]`
- `buildClaudeProfileEnvironment({ baseEnv, profile, secret }) -> Record<string,string>`
- `describeClaudeProfileRuntime({ profile, secretState }) -> ProfileRuntimeStatus`

新增 `electron/claudeRuntimeConfig.js`：

- `resolveClaudeConfigDir({ env, userHome }) -> string`
- `readClaudeRuntimeSnapshot({ env, userHome }) -> { configDir, settingsPath, settingsMtimeMs, inheritedAuthMode }`

`inheritedAuthMode` 只能是 `api_key`、`bearer`、`cloud_provider`、`login_or_unknown`，只根据环境变量是否存在判断，不返回值。

- [ ] **Step 3: 实现最小校验**

```js
const MODEL_PATTERN = /^[a-zA-Z0-9][a-zA-Z0-9._:@/+~-]{0,255}$/
const MODES = new Set(['subscription', 'api_key', 'bearer'])
const PROVIDER_BY_MODE = {
  subscription: 'claude-subscription',
  api_key: 'anthropic-api',
  bearer: 'anthropic-bearer'
}

function profileError(code, message = code) {
  return Object.assign(new TypeError(message), { code })
}

export function isSafeClaudeModel(value) {
  return typeof value === 'string' && MODEL_PATTERN.test(value)
}

export function normaliseClaudeProfileDraft(draft = {}) {
  const name = String(draft.name || '').trim()
  if (!name) throw profileError('INVALID_CLAUDE_PROFILE')
  if (!MODES.has(draft.connectionMode)) throw profileError('INVALID_CLAUDE_PROFILE')
  if (draft.model && !isSafeClaudeModel(draft.model)) throw profileError('INVALID_CLAUDE_MODEL')
  if (draft.connectionMode === 'subscription' && String(draft.baseUrl || '').trim()) {
    throw profileError('INVALID_CLAUDE_PROFILE')
  }
  const baseUrlInput = String(draft.baseUrl || '').trim()
  const baseUrlResult = baseUrlInput ? validateProfileBaseUrl(baseUrlInput) : { ok: true, value: null }
  if (!baseUrlResult.ok) throw profileError('INVALID_PROFILE_BASE_URL')
  return {
    common: {
      adapterId: 'claude',
      name,
      kind: draft.connectionMode === 'subscription' ? 'reference' : 'managed',
      providerId: PROVIDER_BY_MODE[draft.connectionMode],
      baseUrl: baseUrlResult.value,
      model: draft.model || null
    },
    config: {
      connectionMode: draft.connectionMode,
      baseUrl: baseUrlResult.value
    },
    secretAction: draft.secret
      ? { type: 'replace', value: String(draft.secret) }
      : draft.keepSecret
        ? { type: 'keep' }
        : { type: 'none' }
  }
}
```

从 `contracts.js` 导入 `validateProfileBaseUrl`。返回对象必须逐字段构造，不能展开或返回原 draft；Step 4 再对 `secretAction` 与连接方式的组合做严格校验。

## 验收定义

- Claude Code 页签可以创建、编辑、删除、回滚和绑定档案；
- 支持现有登录态、API Key 和 Bearer 网关三种连接方式；
- 同一工作台不同 Claude 会话可使用不同档案；
- 密钥只存在于 OS 加密存储和目标 Claude PTY 环境；
- Bash/hooks/MCP stdio 子进程默认不能继承 UCLI 托管的 Provider 密钥；
- 组织策略替换模型时 UI 显示 requested/actual 差异；
- 历史会话恢复、Gateway 决策、权限 hook 和分屏自动恢复无回归；
- UCLI 不修改 Claude Code 的任何用户、项目、managed 或 OAuth 文件。

## 参考依据

- Claude Code CLI 的 `--settings` 只覆盖提供的 key，未提供的文件设置继续保留；`--model` 是交互会话级参数，而 `--fallback-model` 仅适用于 `--print`，因此 0.8.1 不提供 fallback。<https://code.claude.com/docs/en/cli-usage>
- Claude Code 官方环境变量定义了 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL` 和 `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` 的行为。<https://code.claude.com/docs/en/env-vars>
- Claude Code 恢复会话时可恢复 transcript model，但新启动传入的 `--model` 优先；组织策略仍可能替换请求模型。<https://code.claude.com/docs/en/model-config>
