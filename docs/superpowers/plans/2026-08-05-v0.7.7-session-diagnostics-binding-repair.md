# UCLI 0.7.7 Session Diagnostics and Binding Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Codex session diagnostics dialog that explains the persisted native-session binding and repairs a stale binding to the newest valid main-session descendant, while keeping native `/resume` rebinding visible and persisted immediately.

**Architecture:** A focused main-process service owns diagnosis and repair. It reuses the existing Codex rollout resolver and same-project rollout listing, returns an allowlisted data-only contract through two IPC channels, and persists repairs through the orchestrator. A small Vue component renders the contract; the Pinia session store remains the renderer's single source of session-summary state.

**Tech Stack:** Electron IPC, Node.js filesystem metadata, Vue 3, Pinia, Ant Design Vue, Node test runner, Vue compiler test utilities.

## Global Constraints

- Target release is `0.7.7`.
- A repair may update only the selected UCLI session's `native_session_id`; it must not delete or rewrite Codex rollout files.
- Only Codex main sessions from the UCLI session's normalized project directory are eligible; subagent rollouts remain excluded.
- Diagnostic results expose identifiers, timestamps, status, adapter, and project directory only; they never expose transcript content, credentials, provider secrets, or rollout file paths.
- Existing native `/resume` capture remains the authority when the user explicitly selects a session in the Codex TUI.
- The four pre-existing untracked plans dated `2026-07-28` remain untouched.
