# UCLI 0.9.1 Session Configuration Modal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce per-session workbench clutter by moving low-frequency configuration and lifecycle operations into one reusable configuration modal opened from a settings icon.

**Architecture:** Add a renderer-only `SessionConfigModal` that reuses the existing sessions, profile, Gateway, diagnostics, and Codex runtime APIs; no database or IPC schema changes are required. Keep only high-frequency pane controls in `SessionDetail`, retain compact read-only runtime metrics, and expose the same modal from pane headers, the workbench session sidebar, and overview session cards.

**Tech Stack:** Electron 32, Vue 3 `<script setup>`, Pinia, Ant Design Vue 4, Node test runner, Vue SFC/compiler template tests.

## Global Constraints

- Release version is exactly `0.9.1`.
- Do not add or change SQLite tables, main-process IPC channels, preload methods, or persisted session fields.
- Preserve current behavior for profile switching, Codex Provider policy, Gateway relay, diagnostics, notes, stop/restart, removal, pane history, fullscreen, and workbench restoration.
- Pane headers retain only settings, history/terminal, fullscreen, interrupt, and close-pane controls.
- Stop, restart, remove-from-UCLI, diagnostics, note editing, Gateway relay, profile selection, and Codex Provider selection live in the configuration modal.
- The compact pane information bar remains read-only and contains only model/actual-model and usage metrics; session IDs and configuration selectors move into the modal.
- “Close pane” remains a layout-only action and must never stop or delete the underlying session.
- “Remove from UCLI” remains destructive only to the UCLI record; source CLI history and usage statistics remain retained.
- Running profile switches preserve the existing three-way decision: cancel, apply on next restart, or restart now.
- Configuration warnings remain visible through a badge on the settings icon and detailed text inside the modal.
- No new dependency is allowed for this release.
- All user-facing controls require a Chinese accessible label or tooltip; icon-only buttons require `aria-label`.

- [ ] **Step 3: Implement the minimal pure derivation**

Create `src/sessionConfigPresentation.js`:

```js
const ACTIVE_STATUSES = new Set(['running', 'idle', 'waiting', 'starting'])
const INTERRUPTIBLE_STATUSES = new Set(['running', 'idle', 'waiting'])
const PROFILE_ADAPTERS = new Set(['codex', 'claude'])

export function deriveSessionConfigState(session = {}) {
  const profileCapable = PROFILE_ADAPTERS.has(session.adapterId)
  const providerEditable = session.adapterId === 'codex' && !session.profileId
  let attentionCode = null
  let attentionText = ''

  if (session.restartRequired) {
    attentionCode = 'restart_required'
    attentionText = '配置已变更，重启后生效'
  } else if (session.profileWarning) {
    attentionCode = 'profile_warning'
    attentionText = '配置档案需要处理'
  } else if (session.providerWarning || session.pendingProviderWarning) {
    attentionCode = 'provider_warning'
    attentionText = 'Provider 配置需要处理'
  }

  return {
    profileCapable,
    providerEditable,
    explicitProviderVisible: providerEditable && session.providerPolicy === 'explicit',
    canInterrupt: INTERRUPTIBLE_STATUSES.has(session.status),
    canStop: ACTIVE_STATUSES.has(session.status),
    canRestart: session.canStart !== false,
    needsAttention: Boolean(attentionCode),
    attentionCode,
    attentionText
  }
}
```

async function saveBasics() {
  const current = session.value
  if (!current) return
  const name = nameDraft.value.trim()
  if (!name) {
    message.warning('会话名称不能为空')
    return
  }
  savingBasics.value = true
  try {
    if (name !== current.displayName) await sessions.updateName(current.id, name)

}
