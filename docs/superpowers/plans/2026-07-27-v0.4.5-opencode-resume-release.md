# UCLI v0.4.5 OpenCode Resume Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release UCLI v0.4.5 with OpenCode history recovery automatically targeting the imported source session without overriding its historical provider or model.

**Architecture:** Keep the existing OpenCode PTY adapter and session database unchanged. For imported OpenCode sessions, start the native TUI with only `--session <source-id>` so OpenCode loads the exact context and its historical provider/model; retain model arguments for new sessions. Keep `/session` available as an unmodified native TUI command for manual switching. Publish through the repository's existing electron-builder and tag-triggered GitHub Actions workflow.

**Tech Stack:** Electron 32, Node.js, node-pty, Vue 3, electron-vite, electron-builder, Node test runner, GitHub Actions.

## Global Constraints

- Release version is exactly `0.4.5`.
- Windows x64 is the local acceptance platform.
- OpenCode must retain its native TUI and native `/session` selector.
- Existing UCLI sessions, audit records, rules, and statistics must remain compatible.
- Do not delete or rewrite native OpenCode session data.
- GitHub Release is created only after local tests, build, artifact verification, and installed-app acceptance succeed.
